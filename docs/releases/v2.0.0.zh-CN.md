# ContractGuard 2.0.0：让 API 变更审查连接调用代码与已有测试

ContractGuard 2.0 将契约检查、调用方迁移和项目已有测试整合为一条本地审查流程，通过更新后的网页工作台、CLI 和 MCP 插件使用。

响应字段改名后，一份有用的审查应该说明：哪些已提供的调用代码读取了这个字段，新响应会触发什么问题，以及迁移建议能否通过项目原有断言。ContractGuard 把这些证据关联起来，同时保留 API 变更本身的兼容性门禁。

## 本次亮点

- **围绕证据整理的工作台。** 更新工作区布局、字体和视觉层次，改善窄屏阅读，让契约输入、任务进度、调用位置和测试阶段更容易查找。普通分析、保存的 AI 解读和历史仍可使用。
- **贯通契约、调用方、迁移与测试。** 注册项目后，一次审查可以组合确定性契约发现、有限 TypeScript 重放、显式字段迁移，以及基线/候选/补丁副本上的真实 Node/Vitest 测试。原项目源码保持不变。
- **复用已有 fixture 与断言。** 本机注册表一次声明源码、响应文件和固定测试，网页与 Agent 只需选择项目 ID，减少重复整理材料。
- **MCP 与网页共用审查记录。** 19 个工具覆盖分析、Agent 审查、调用方证据、项目发现、保存的解读、历史、取消和完整报告导出；可生成 Codex、Antigravity、DeepSeek Harness 与通用 MCP 配置。
- **可观察的大模型编排。** workflow 不需要模型；LLM 模式在允许的检查中选择动作并形成关联证据的建议。必要检查不能省略，确定性门禁不能由模型改写，DeepSeek Key 留在服务进程。
- **一致的 2.0 交付。** 自有包、运行时版本和插件清单统一为 `2.0.0`，中英 README、详细使用指南和升级检查与当前产品一致。

## 运行完整示例

安装 Node.js 22.13+、pnpm 11.19.0，下载或克隆源码，在 Windows 仓库根目录运行：

```powershell
.\start-contractguard.bat --install --projects .\fixtures\project-tests\demo-registry.json --no-ai
```

打开 `http://127.0.0.1:8080`，在 Agent 工作区选择注册项目 `orders-migration`，运行 workflow 审查。示例把 `customerName` 改为 `displayName`，已有测试表现为 **2 项通过 → 1 项通过 / 1 项失败 → 2 项通过**。最后一步验证显式重命名候选；原门禁仍为阻断，因为调用方补丁通过不等于 API 变更向后兼容。

其他系统、AI 配置及自己的项目接入见 [2.0 使用指南](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-user-guide.md)。

## 安装 MCP 插件

保持本地服务运行，在源码目录执行 `pnpm plugin:prepare`。Codex CLI 可用 `pnpm plugin:prepare --codex` 注册，其他宿主合并生成的配置片段。

发布附件 **ContractGuard-Agent-Plugin-2.0.0.zip** 包含可移动插件运行文件和使用说明，需要 **Node.js 以及单独启动的 ContractGuard 服务**，不是独立桌面安装程序。`SHA256SUMS.txt` 提供压缩包校验值。[使用指南](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-user-guide.md#6-在-codexantigravity-或其他-agent-中使用)包含源码与压缩包接入方法。

## 升级说明

保留实际数据目录、本地模型配置和项目注册表，按锁文件安装依赖、重新构建并重启服务。运行路径或端口变动后，重新生成插件配置。

- 报告 `schemaVersion` 仍为 **1**；旧的已完成分析、Agent 和调用方记录保持原始版本信息并可继续读取。
- 回归包显式接受 **1.5.0** 与 **2.0.0**。旧包保留创建版本及校验值，新重放结果标明当前引擎；未知版本和被篡改的包仍拒绝。这是明确限定的兼容支持，不代表任意旧版本可直接重放。
- 集成的官方 oasdiff 仍为 **1.35.0**，与 ContractGuard 自有版本号独立。

## 验证与边界

[2.0 验证记录](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-verification.md)记录自动化检查、升级重放、实际页面验收、Codex 插件检查和公开项目对照。此前的[真实 DeepSeek 验收](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v1.8-deepseek-acceptance.md)保留 V1.8 标识，不作为本轮 2.0 再次调用云模型的证明。

调用方重放只支持有限 TypeScript 子集；迁移建议需要明确且受支持的映射。注册测试在源码副本中执行可信 Node.js 代码，**不是操作系统沙箱**。选定测试通过无法证明所有调用方安全。模型引用校验可以确认引用存在，自然语言建议仍需审阅。
