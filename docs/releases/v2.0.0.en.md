# ContractGuard 2.0.0 — API changes with caller and test evidence

ContractGuard 2.0 brings contract checks, caller migration and existing project tests into one local review workflow, available through a refreshed Web workbench, CLI and MCP plugin.

When a response field changes, a useful review should show more than the removed field: where a supplied caller reads it, what happens with the new response, and whether a proposed migration survives the project's existing assertions. ContractGuard connects those steps while preserving the original compatibility gate.

## Highlights

- **An evidence-focused workbench.** A clearer workspace, quieter visual hierarchy and responsive layouts keep contract inputs, task progress, caller locations and test phases readable. Ordinary analysis, saved AI explanations and history remain available.
- **Contract → caller → migration → tests.** Review a registered project to combine deterministic contract findings, bounded TypeScript caller replay, explicit field-rename proposals and real Node/Vitest execution on baseline, candidate and patched copies. The original source is unchanged.
- **Use existing fixtures and assertions.** An operator-owned registry describes source paths, response fixtures and fixed test files once. Web and Agent clients select a project ID instead of resubmitting material or choosing arbitrary commands.
- **MCP that shares the workbench's records.** Nineteen tools expose analysis, Agent reviews, caller evidence, project discovery, saved explanations, history, cancellation and complete report export. Generated integration fragments cover Codex, Antigravity, DeepSeek Harness and general local MCP hosts.
- **Optional model planning, observable decisions.** Workflow mode needs no model. LLM mode can select allowed checks and produce evidence-linked recommendations; mandatory checks and deterministic gates remain enforced. DeepSeek credentials stay in the service process.
- **A coherent 2.0 release.** All first-party packages, runtime identifiers and plugin manifests use `2.0.0`. The English/Chinese README, detailed user guide and upgrade checks now describe the same product.

## Try the complete example

Install Node.js 22.13+ and pnpm 11.19.0, download/clone the source, then on Windows run:

```powershell
.\start-contractguard.bat --install --projects .\fixtures\project-tests\demo-registry.json --no-ai
```

Open `http://127.0.0.1:8080`, select the Agent workspace and registered project `orders-migration`, then start a workflow review. The supplied example changes `customerName` to `displayName`. Its existing tests show **2 passed → 1 passed / 1 failed → 2 passed** after the explicit rename proposal. The original gate remains blocked: a successful caller patch does not make the API change backward-compatible.

For other platforms, AI setup and project registration, use the [2.0 user guide](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-user-guide.md).

## Install the MCP plugin

With the local service running, execute `pnpm plugin:prepare` from the source checkout. Use `pnpm plugin:prepare --codex` for Codex CLI registration, or merge the generated host configuration fragment.

The release attachment **ContractGuard-Agent-Plugin-2.0.0.zip** contains the portable plugin runtime and instructions. It requires **Node.js and a separately running ContractGuard service**; it is not a standalone desktop application. `SHA256SUMS.txt` supplies the archive checksum. The [user guide](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-user-guide.md#6-在-codexantigravity-或其他-agent-中使用) explains archive and source installation.

## Upgrade notes

Keep the actual data directory and local provider/project configurations, reinstall locked dependencies, rebuild and restart the service. Regenerate plugin files if runtime paths or service ports changed.

- Report `schemaVersion` remains **1**. Existing completed analysis, Agent and caller records remain readable with their original version metadata.
- Regression-pack replay explicitly accepts **1.5.0** and **2.0.0**. Old packs retain their original version and checksum; replay reports identify the current engine. Unknown engine versions and modified packs remain rejected. This is a specific compatibility allowance, not an unrestricted semantic-version range.
- The integrated official oasdiff binary stays at **1.35.0**; its version is independent of ContractGuard's release number.

## Verification and limits

The [2.0 verification record](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v2.0-verification.md) records the automated suite, upgrade replay checks, actual browser acceptance, Codex plugin checks and public-project benchmark. The earlier [real DeepSeek acceptance](https://github.com/Reizen721/ContractGuard/blob/v2.0.0/docs/v1.8-deepseek-acceptance.md) remains labelled V1.8; it is not presented as a fresh 2.0 cloud run.

Caller replay supports a bounded TypeScript subset. Migration proposals need explicit supported mappings. Registered tests execute trusted Node.js code in source copies, **not an OS sandbox**. Passing selected tests does not establish compatibility for all consumers. Model reference validation confirms evidence exists; natural-language advice still needs review.
