# ContractGuard MCP v1.6.0 — 让 Agent 基于证据审查 API 变更

*本地发布草稿，尚未创建 GitHub Release。下文固定到 `v1.6.0` 的链接与克隆命令，需要先发布对应源码和标签才能使用。*

接口新增一个必填请求头，服务端文档仍然合法，旧客户端却可能开始报错。发布前，团队需要知道改了什么、哪些已有调用方式受到影响，以及迁移建议依据哪条检查结果。

**ContractGuard MCP 把这套审查流程交给你正在使用的 Agent。** 提供新旧 OpenAPI 契约和调用方样例后，Agent 可以执行分析、追查证据、生成迁移建议，并在后续会话中查看已保存的记录。网页和 Agent 访问同一个本机服务，共享分析历史与报告。

## 本次发布带来了什么

- **14 个 MCP 工具。** 覆盖状态检查、规则查询、创建分析、读取证据、查询历史、AI 解读、完整审查、取消任务和报告导出。
- **延续已有契约能力。** 接收 OpenAPI 3.0/3.1 的 YAML、JSON 和显式本地多文件包，保留输入指纹及未覆盖范围提示。完整审查组合官方 **oasdiff 1.35.0** 与 ContractGuard 原生检查。
- **加入调用方视角。** 检查用户提供的请求、响应样例和响应约束，区分回归、无效基线与无法确定的情况，将结果关联到迁移任务。它不会自动发现所有客户端，也不向真实业务服务重放请求。
- **分析结果可以继续查。** 普通分析、完整审查和已保存的 AI 解读可查询、导出；支持 JSON、Markdown，普通分析还可导出 HTML。大报告分块返回，保留完整内容。
- **AI 按需参与。** 外部 Agent 可以直接调用确定性 `workflow`；需要进一步解释或规划时，显式使用服务端已配置的 DeepSeek 等模型。模型建议引用的证据会被校验，模型不能修改确定性的发布门禁结论。
- **可移动插件与宿主配置。** 提供 portable Agent Plugin、Codex 兼容清单、使用 skill，以及 Codex、Antigravity、DeepSeek Harness 配置生成器。

原有网页、CLI、回归包和模型配置继续保留。插件版本为 **1.6.0**，原生引擎保持 **1.5.0**。上游规则能力归属于 oasdiff，授权信息见[第三方声明](https://github.com/Reizen721/ContractGuard/blob/v1.6.0/THIRD_PARTY_NOTICES.md)。

## 从源码开始

需要 **Node.js 22.13+、pnpm 11.19.0 和 Git**。插件依赖单独运行的 ContractGuard 本机服务。

```powershell
git clone --branch v1.6.0 https://github.com/Reizen721/ContractGuard.git
cd ContractGuard
pnpm install --frozen-lockfile
pnpm engine:install
pnpm build
pnpm plugin:prepare
pnpm start
```

保持服务运行，默认地址为 `http://127.0.0.1:8080`。Windows 可以用 `start-contractguard.bat` 代替最后一条命令；需要 DeepSeek 时，在启动器的隐藏输入提示中填写 Key。确定性分析和 `workflow` 无需 DeepSeek Key。

在另一个终端进入同一项目目录，为支持本地插件目录的 Codex 安装完整插件：

```powershell
codex plugin marketplace add ./.tools/agent-plugin
codex plugin add contractguard@contractguard-local
```

其他宿主可合并 `.tools/agent-plugin/` 下对应的配置片段：通用 `mcp-config.json`、Codex 的 `codex-config.toml`、Antigravity 的 `antigravity-mcp.json`，或 Harness 的 `deepseek-harness.cordis.json`。保留已有配置；Codex 的完整插件与直接 MCP 配置选择一种安装方式。

安装后开启新会话。详细步骤、宿主差异与完整工具参数见[插件接入指南](https://github.com/Reizen721/ContractGuard/blob/v1.6.0/docs/v1.6-agent-plugin.md)。

## 试一次完整审查

在有权读取本仓库的 Agent 中输入：

> 先检查 ContractGuard 状态。读取 `fixtures/consumer-impact/baseline.json`、`fixtures/consumer-impact/candidate.json` 和 `fixtures/consumer-impact/consumers.json`，用原始内容创建普通分析，再以 workflow 模式启动完整审查。等待审查结束，列出确定性结论、上游破坏性变更、调用方回归和迁移建议。查询历史确认两条记录已保存，将完整审查报告导出为 Markdown；如果报告分块，读取全部块。区分“执行完成”和“发布通过”。

这是不含凭据的合成零售样例。当前引擎下，完整审查应得到 **`blocked`、2 项上游 breaking、3 项调用方回归**。这个阻断结果正是测试预期。

## 使用范围

本版面向能启动本地进程的 **MCP stdio** 宿主，没有托管 HTTP MCP 入口。可移动插件包含所需 JavaScript 依赖，但不包含整个 API 平台或 oasdiff 二进制；安装插件之后仍需启动服务。

确定性分析和历史存储在本机。使用云端 Agent 或显式启用云端模型时，相应内容会进入该模型服务的数据处理流程，因此“本地优先”不代表所有材料始终不出本机。密钥由服务端管理，不作为 MCP 工具参数。

结果表示已实现规则和已提供证据下的判断。`compatible=true` 仍可能包含潜在风险；有限样例通过不能证明生产安全。请同时查看未覆盖范围、调用方结果和发布门禁。欢迎提交脱敏、可复现的误报或漏报案例。
