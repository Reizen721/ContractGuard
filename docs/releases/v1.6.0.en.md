# ContractGuard MCP v1.6.0 — Evidence-backed API change reviews for agents

*Local release draft. The source checkout and `v1.6.0` tag must be published before the tag links and checkout command below become available. This document does not indicate that a GitHub Release or npm package has been published.*

ContractGuard MCP lets an agent analyze an API change, inspect supporting evidence, and return to the saved review later. Its **14 MCP tools** connect to the same local service as the existing web application, so agents and people share analysis history, review progress, and exported reports.

## What is included

- **Contract analysis:** OpenAPI 3.0/3.1 YAML or JSON, explicit local multi-file bundles, input fingerprints, and warnings about unsupported or inconclusive coverage.
- **Bounded reviews:** validation, breaking-change checks, native analysis, migration recommendations, progress queries, and cancellation. Full reviews reuse the official **oasdiff 1.35.0** engine alongside ContractGuard's native checks; upstream functionality remains attributed to oasdiff.
- **Consumer evidence:** evaluate supplied request/response samples against the contracts and retain the resulting findings. This requires explicit samples; it does not automatically scan consumer repositories or replay requests against live services.
- **Persistent results:** shared analysis and review history, saved AI explanations, and JSON/Markdown exports; ordinary analyses also support HTML export. Larger reports are returned in lossless chunks.
- **Optional AI:** DeepSeek or another configured provider can explain findings or plan a bounded review. Evidence references are validated, and model suggestions cannot override deterministic gates. Model credentials stay with the service and are not MCP tool inputs.

The package contains a portable Agent Plugin, Codex compatibility manifests, a workflow skill, and generated configuration fragments for Codex, Antigravity, and DeepSeek Harness. The web application and CLI remain available. The MCP/plugin version is **1.6.0**; the unchanged native engine remains **1.5.0**.

## Quickstart from source

Requirements: **Node.js 22.13+**, **pnpm 11.19.0**, and Git. The adapter requires a **separately running local ContractGuard API**; installing the plugin alone does not start the platform.

```bash
git clone --branch v1.6.0 https://github.com/Reizen721/ContractGuard.git
cd ContractGuard
pnpm install --frozen-lockfile
pnpm engine:install
pnpm build
pnpm plugin:prepare
pnpm start
```

Keep the service running at `http://127.0.0.1:8080`. On Windows, `start-contractguard.bat` is an alternative to `pnpm start`; its hidden input prompt is the place to enter an optional DeepSeek key.

In another terminal, from the same checkout, install the complete plugin into a Codex version supporting local marketplaces:

```bash
codex plugin marketplace add ./.tools/agent-plugin
codex plugin add contractguard@contractguard-local
```

Alternatively, merge the appropriate generated fragment under `.tools/agent-plugin/` into your host configuration: `mcp-config.json`, `codex-config.toml`, `antigravity-mcp.json`, or `deepseek-harness.cordis.json`. Preserve existing entries and choose one Codex installation method. Open a new host conversation after installation.

Try: “Check ContractGuard status. Analyze the baseline, candidate, and consumer samples in `fixtures/consumer-impact/`, run a `workflow` review, retrieve its evidence and history, and export the Markdown report.” Deterministic analysis and `workflow` do not require a DeepSeek key.

See the [installation and tool guide](https://github.com/Reizen721/ContractGuard/blob/v1.6.0/docs/v1.6-agent-plugin.md) for host-specific setup, input formats, and safe retry behavior.

## Scope

This is a local **MCP stdio** integration for hosts that can launch local processes. It does not provide a hosted HTTP MCP endpoint or establish compatibility with every agent framework. The generated adapter bundle includes its JavaScript dependencies; the API service and oasdiff installation remain separate requirements.

Deterministic checks and history storage run locally. A cloud-based agent host can still send submitted material and tool results to its own model provider; explicitly enabling a cloud model in ContractGuard also involves that provider. Local-first deployment is not a promise that all data remains on the machine.

The ten host cases cover representative single contract changes, not all OpenAPI semantics or production behavior. `compatible=true` can coexist with potentially-breaking findings. Read coverage warnings, consumer evidence, and deterministic gates before making a release decision. Upstream acknowledgements and license terms are recorded in [third-party notices](https://github.com/Reizen721/ContractGuard/blob/v1.6.0/THIRD_PARTY_NOTICES.md).
