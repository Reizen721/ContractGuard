# V1.5：带官方引擎的 API 评审 Agent

本地源码版本：1.5.0。本文描述本地实现，不表示已经推送、发布或通过远程 CI。

本次把 ContractGuard 组织为“提交材料 → 执行检查 → 查看证据 → 安排迁移”的工作台。底层接入固定版本的 oasdiff，保留调用方样例检查，上层提供可保存、可取消、可复核的任务流程。

## 与 oasdiff 的关系

项目直接调用 Apache-2.0 许可的官方 **oasdiff 1.35.0**，不把上游规则包装为自研。源码固定在提交 [a4ba100f880c7579765c5e63915a99bf1acc6967](https://github.com/oasdiff/oasdiff/tree/a4ba100f880c7579765c5e63915a99bf1acc6967)。安装器验证官方发布包的 SHA-256，许可见[第三方声明](../THIRD_PARTY_NOTICES.md)。

| 入口 | 能力 |
| --- | --- |
| 本地 `contractguard oasdiff …` | 原样传递完整官方 CLI 的命令、参数、输入输出与退出码，包括 breaking、changelog、diff、summary、validate、flatten、upgrade、Git 集成、规则与覆盖目录 |
| Web / HTTP Agent | 白名单工具：两侧校验、破坏变更、变更日志、ContractGuard 调用方检查，以及按需 diff / summary；只处理本次提交材料 |
| 原有兼容性分析 / `compare` | 保留自有规则、分数、覆盖提示与调用方检查的语义 |

完整 CLI 可用不等于每一个上游参数都有网页控件，也不代表复刻 oasdiff.com 托管服务。Agent 不执行任意终端命令，不向真实后端发送测试请求，不把模型意见作为兼容性判定。详细对应关系见[能力矩阵](oasdiff-capabilities.md)。

固定版本目录含 778 条 changelog 检查、121 条 validate 检查。这是上游目录条目数，不是准确率或自研规则数量。各命令支持的格式以 `--help` 为准；本版上游没有 SARIF 格式。

## 首次启动

Windows 在项目目录运行：

```powershell
.\start-contractguard.bat --install --no-ai
```

安装参数会安装依赖、下载并校验固定引擎，再构建应用。首次安装需要联网；普通本地工作流无需模型密钥。手动方式：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd engine:install
pnpm.cmd build
pnpm.cmd start
```

打开 `http://localhost:8080`。载入“调用方示例”，将两份契约与调用方证据送入 Agent。合成零售示例包含新增必填参数、提高购买数量下限、候选响应缺失调用方所需字段，预期出现阻断及相关证据。原有单次分析、AI 报告解读、历史与导出仍可独立使用。

若提示缺少引擎，运行 `pnpm.cmd engine:install` 后刷新状态。受管安装目录为 `.tools/oasdiff/1.35.0/`。管理员可通过 `CONTRACTGUARD_OASDIFF_PATH` 指定同版本可执行文件：来源由配置者负责，程序检查版本，不把自选文件冒充经过安装器校验的发布包。

## 两种模式

**本地工作流（workflow）** 不调用大模型，按既定顺序检查并形成确定性结论与迁移清单。它是自动流程，不宣称模型自主规划。

**模型规划（llm）** 使用服务端已经配置并启用的模型。模型根据有限步骤摘要、计数及允许引用的证据编号选择下一项白名单工具，检查完成后生成迁移建议。服务端检查工具名、预算、重复调用和证据引用，未完成必需检查不能正常结束。错误模型输出会明确失败，不会自动改成通过。

两种模式均可取消和保存任务。原始契约及调用方样例只在任务执行期间留在内存；保存结果包含指纹、分析结论和必要证据元数据。重启后未完成的记录标为中断，不自动重跑。任务目录应由一个进程独占；CLI 默认 `data/agent-cli`，API 使用分析目录下的 `agent-runs`，不要将二者配置到同一目录同时运行。

模型规划沿用服务端 AI 配置，具体见 [AI 设置](ai-report-interpreter.md)。启用 DeepSeek 后，在页面显式选择模型规划才会调用规划模型。普通 AI 解读是另一项功能：解释已有报告，不选择工具。

### 用 DeepSeek 开始自主审查

在项目根目录运行这一条命令。已有本地专用配置时，用你的文件替换示例路径：

```powershell
.\start-contractguard.bat --install --config .\config\llm-providers.example.json
```

启动器用隐藏输入提示填写 `DEEPSEEK_API_KEY`，兼容 Windows PowerShell 5.1。不要把密钥发到聊天或写进源码。安装完成后再启动，可以省略 `--install`。

打开 `http://localhost:8080`，依次选择“载入调用方示例”→“交给 Agent 审查”→“LLM 自主编排”→“开始审查”。任务结束后查看确定性结论、检查过程和迁移事项，并导出 Markdown / JSON。一次任务需要多次模型决策，均受时间、输出和步骤限制。密钥无效、额度或网络错误会明确失败，不会伪造成功报告。

示例使用 `deepseek-flash`、JSON Object 输出并关闭 thinking，配置与 2026-11-02 查阅的 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)及 [JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)一致。模型可用性由服务商决定。自动化套件使用模拟回复；随后另用用户在本机输入的密钥完成了真实云端审查，5 步检查、6 次模型调用正常结束，见[验证记录](verification.md)。这一次成功不代表所有输入或模型输出均已验证。

不发送原始样例不等于完全匿名化。任务目标、工具摘要和受限证据元数据仍可能透露业务含义，输入前应删去无关敏感描述。密钥留在服务端；模型没有任意读取本机文件、调用 URL 或运行程序的权限。

## 命令行

查看官方帮助和规则目录：

```powershell
pnpm.cmd contractguard oasdiff --help
pnpm.cmd contractguard oasdiff breaking fixtures/petstore-v1.yaml fixtures/petstore-v2-breaking.yaml --format json --fail-on ERR
pnpm.cmd contractguard oasdiff checks changelog --format json
pnpm.cmd contractguard oasdiff checks changelog coverage --help
```

此入口保留上游文件、URL、Git 引用、标准输入和配置行为。只有用户直接执行的本地命令能使用这些能力，网页 Agent 不会代为执行 `--open`、`--fetch` 或任意远程引用。上游 `--fail-on` 通常使用退出码 1，不要套用自有 compare 的退出码 2。

完整本地评审：

```powershell
pnpm.cmd contractguard agent fixtures/consumer-impact/baseline.json fixtures/consumer-impact/candidate.json --consumer-evidence fixtures/consumer-impact/consumers.json --output agent-review.md
```

使用配置好的规划模型：

```powershell
pnpm.cmd contractguard agent fixtures/consumer-impact/baseline.json fixtures/consumer-impact/candidate.json --consumer-evidence fixtures/consumer-impact/consumers.json --mode llm --output agent-review.md
```

`--provider <id>` 需要 llm 模式且服务端允许选择模型。多文件输入使用 `--bundle`，必要时明确 `--baseline-root` 和 `--candidate-root`；`--data-dir` 指定任务目录；`--format` 支持 json / markdown。

Agent CLI：0＝完成且 pass；2＝完成但 review / blocked；1＝输入、工具或模型执行失败；130＝取消。没有调用方证据的任务最多是 review；有限样例不能证明所有调用方安全。

## 读懂结果

- **pass**：本次材料下的必需检查完成，未发现阻断或待复核条件。
- **blocked**：规范校验、确定性变更规则或调用方检查出现明确阻断，先检查证据，再决定修复与迁移。
- **review**：缺少证据、存在未覆盖范围或不能支持通过，需要人工复核。
- **failed / cancelled / interrupted**：任务没有正常完成，均不表示通过。

上游和自有结果可能不同，不把两者分数平均，也不让模型消除确定性发现。OpenAPI 3.2 可以交给上游处理；自有规则或调用方验证不支持的范围保留为待复核，不宣称端到端完整支持 3.2。

## API

新增路由前缀 `/api/agent`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/status` | 引擎、模型与执行限制 |
| POST | `/runs` | 提交 baseline、candidate 和可选 consumerEvidence / goal / mode / providerId |
| GET | `/runs` | 本地任务列表 |
| GET | `/runs/:id` | 步骤、证据、结论和建议 |
| POST | `/runs/:id/cancel` | 取消任务 |
| GET | `/runs/:id/report?format=markdown` | 导出 Markdown；format=json 导出结构化结果 |

这是单机评审工具，默认监听回环地址，尚无多用户认证与权限隔离。详见 [Agent 设计](agent-design.md)和[安全边界](../SECURITY.md)。下一阶段若扩展到修改调用方代码、运行项目测试或创建 PR，需要另行设计仓库权限、隔离执行与人工审阅。本次落实“分析材料 → 执行检查 → 迁移建议”。
