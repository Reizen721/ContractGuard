# V1.2 升级与验收指南

V1.2 的重点是让检测结果更可信、报告来源更明确，并把 AI 解读保存在本机供后续复核。它不改变“规则引擎决定兼容性，模型只负责解释”的边界。

## 1. 升级现有安装

先停止旧的 ContractGuard 服务，在项目目录运行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd check
.\start-contractguard.bat
```

也可以使用 `.\start-contractguard.bat --install` 安装、构建并启动；已经安装新依赖时，使用 `--build` 重建。浏览器打开 `http://localhost:8080`，刷新旧页面以加载新版资源。

不要把运行中的数据目录替换为 GitHub 下载包。升级前可在停止服务后备份 `data/analyses/`，自定义部署则备份 `CONTRACTGUARD_DATA_DIR` 指定的目录。V1.0/V1.1 分析记录可以继续读取；没有输入或策略指纹的旧报告会保留缺失状态，不伪造审计信息。旧版本没有保存的 AI 解读无法追溯恢复，需要用户主动重新生成。

## 2. 规则变化与门禁

V1.2 修复了以下类别的遗漏：

- OpenAPI 3.0 的布尔排他边界与 3.1 的数值排他边界按各自语义比较；例如从 `x >= 0` 改为 `x > 0` 不再无提示通过。
- 组合 Schema 不再按分支数量推断安全性。`oneOf` 增加分支可能让原值同时命中多支；无法证明兼容的组合变化会提示人工复核。
- 查询参数的序列化选项、响应头等变化纳入检查，并对缺省值和大小写进行适当归一化。
- 请求对象属性变化结合额外属性策略判断，避免把新增可选但带类型约束的字段一概当作兼容。

相同的输入在新版中可能出现更多风险，分数和 `CG-0001` 等报告内序号也可能变化。这不意味着旧数据被修改：旧报告保留原引擎版本，新分析使用 1.2.0。序号只用于单份报告内引用，不是跨版本稳定的例外标识。

默认 `--fail-on breaking` 仍只阻止确定性的 breaking；`potentially-breaking` 应人工评审，严格团队可使用 `--fail-on potentially-breaking`。没有 breaking 不等于对所有 Schema、运行时行为或业务兼容性的证明。

## 3. 页面中的输入与报告

每次分析都关联提交时的输入，而不是请求完成时编辑器里的文本。修改输入后，应以页面的报告来源与过期提示为准，重新运行分析后再解释或导出新的结论。

清空工作区、载入示例或打开另一份历史报告时，过期请求不能覆盖当前结果。历史报告只代表当时保存的规范与规则；系统不会为恢复编辑器而暗中把完整客户规范写入浏览器缓存。

报告会展示引擎、策略与可用的输入指纹。缺少这些字段的旧记录仍可查看，但不能声称具备新版的来源核验信息。

## 4. AI 解读保存与复用

完成规则分析后，按原方式选择档案、填写关注点并生成解读。成功且通过校验的结果会保存到分析关联的本地目录。重新打开历史或刷新页面，可以读取已保存解读；读取和下载本地历史不调用模型，即使 AI 当前关闭也可进行。

接口如下：

| 操作 | 接口 |
| --- | --- |
| 读取已保存解读 | `GET /api/analyses/{id}/ai-reviews` |
| 生成或复用解读 | `POST /api/analyses/{id}/ai-review` |
| 下载 JSON / Markdown | `GET /api/analyses/{id}/ai-reviews/{reviewId}/report?format=json` 或 `format=markdown` |

相同分析、模型配置、提示词版本、语言和关注点可以复用成功结果；模型或相关配置改变后不复用旧缓存。显式传入 `"force": true` 可重新生成，可能再次产生云端费用。失败、取消或未校验的输出不会作为成功报告保存。

```powershell
# $analysis.id 来自一次已完成的 POST /api/analyses 请求
$baseUrl = 'http://localhost:8080'
$review = Invoke-RestMethod -Method Post `
  -Uri "$baseUrl/api/analyses/$($analysis.id)/ai-review" `
  -ContentType 'application/json; charset=utf-8' `
  -Body '{"language":"zh-CN","focus":"优先解释旧客户端的迁移风险"}'

# 仅读取磁盘中已保存的结果，不调用上游
$saved = Invoke-RestMethod "$baseUrl/api/analyses/$($analysis.id)/ai-reviews"
$saved.reviews | Select-Object id, providerLabel, model, generatedAt
```

完整请求限制与错误码见 [REST API](./api-reference.md)，模型配置见 [AI 指南](./ai-report-interpreter.md)。删除分析时会同时删除关联解读；历史内容可能包含内部端点名和模型生成的业务解释，应像原分析记录一样保护、备份和控制访问。

## 5. 证据覆盖与可信度

解读中的 `coverage` 记录全量 finding 数、实际发送数量、遗漏数量和允许引用的 ID。模型不能引用未发送给它的 finding；被截取的内容不会冒充已被分析。

结构校验、ID 校验和本地保存只能证明格式及引用关系符合要求，不能证明自然语言推断正确。模型的风险排序、消费者影响和迁移建议仍须人工核对，且始终不能改变规则 severity、分数、`compatible` 或 CI 退出码。`affectedConsumers` 是模型提出的可能影响对象，不是生产流量或真实客户端发现结果。

## 6. 复现本版检查

```powershell
pnpm.cmd check
# 已构建后，只运行跨入口原子回归
pnpm.cmd regression
```

除了原有构建、类型检查和集成样例，V1.2 增加规则边界回归、真实 Vue 组件交互测试、AI 证据/保存/复用/取消测试，并用相同原子规范比较核心、REST API 和 CLI 的语义输出。

默认验证使用受控的 fake provider，不读取用户的云端 key，也不产生模型费用。实际通过情况、测试数量与未验证项见 [验证记录](./verification.md)。独立 GitHub Action、单条风险例外、多人权限和完整组合 Schema 求解不属于本版范围。
